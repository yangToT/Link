# 实施顺序与验收

当前实现与验证结果见 validation.md。下方为验收基线，不代表均已完成。

## 第一阶段：验证关键网络链路

在开发正式界面前验证：

- 无域名公网 IP 接入、服务端身份验证和初始管理员注册。
- Windows 设备后台连接、重启后未登录状态恢复。
- 两端无公网 IP 时的直连尝试、中继回退及实际吞吐。
- 管理网页和管理 API 的私有访问与公网隔离。
- Windows 入口到资源网络的访问，以及未安装客户端的调用方反向访问客户端服务。
- 配置撤销、已有连接终止和失联后的状态语义。

本阶段产出明确的版本选择、可运行验证步骤、结果、失败边界及恢复方法。不得用 UI 演示替代网络验证。

## 第二阶段：完成产品服务端与后台服务

实现设备身份、加入凭据、权限、设备生命周期、入口选择、配置下发、持久化、恢复和操作记录。实现服务映射分配与健康状态。

固定接口和数据模型，保持实现简单；不为未确认的 SaaS、计费或插件市场搭建额外体系。

## 第三阶段：完成管理网页与客户端

依据原型实现设备与入口管理、服务映射、连接设置、远程桌面快捷操作。实现原生毛玻璃和实色回退，区分连接、入口和服务的可用状态。

支持通用服务发布，并针对已选择的应用框架实现启动参数生成与 IDEA 接入说明。

## 第四阶段：自托管与发布

提供安装包、部署配置、升级与回退、管理员恢复、配置备份、诊断、卸载清理和第三方声明。

## 验收矩阵

| 项目 | 通过条件 |
| --- | --- |
| 首次接入 | 无域名环境中，从服务端安装输出加入首台管理员设备，无私有页面循环依赖 |
| 管理隔离 | 知道地址的公网访问者也不能访问管理网页及管理 API |
| 多设备 | 四台设备能够加入，权限和身份彼此独立 |
| 入口角色 | 管理端变更后，相关客户端身份标识、访问规则同步更新 |
| 原地址访问 | 客户端能使用资源原地址完成网页及数据库操作 |
| 原生远程桌面 | 支持作为 RDP 主机的设备能够通过 mstsc 互连 |
| 反向访问 | 未安装客户端的实际调用方成功访问远端客户端服务 |
| 应用接入 | IDEA 使用生成的启动配置完成注册与真实调用，断点调试不受影响 |
| 重启与断网 | 自动恢复后台连接与映射，状态准确，不误报健康 |
| 撤销 | 踢下线与停用作用于真实访问，自动重连不绕过停用 |
| 冲突 | 相同本机服务端口不冲突；网段重叠不静默连接错误目标 |
| 清理 | 断开、卸载和回退不会破坏其他应用的系统网络配置 |
| 分发 | 无真实凭据；许可证与依赖声明完整；部署和恢复文档可执行 |

界面验证、单机验证、跨网络验证和部署验收分别记录，不合并表述为“全部完成”。

## 二层接入源码变更

`NetworkDiscovery.cs` 负责真实物理网卡选择；`Layer2.cs` 和内嵌 PowerShell 负责专属组件调用、虚拟网卡保护和恢复日志；`server/layer2.go` 通过固定证书的本机 JSON-RPC 管理设备授权、角色和会话撤销。管理网页继续内嵌服务端。

此变更保持可选、默认关闭。0.2.0-alpha.1 包含集成代码，运行验证以 validation.md 为准。SoftEther 二进制的固定版本、签名检查、完整安装包，以及两端真实 LAN/TUN 验收仍未完成，不能把本地替身测试记为网络验证。[完整说明](layer2.md)。
