# Link 0.2.0-alpha.17

修复虚拟网卡创建结果待确认时的恢复死循环，以及网络清理失败后“断开并停止后台”无法停止服务、关闭界面的问题。

- 创建成功先持久化结果，再等待 Windows 网卡识别；恢复时核对 GUID、安装进程和 PnP 状态。没有归属证据的旧恢复记录继续保留，不能按网卡名称自动接管或删除。
- 删除网卡后回读确认；未完成的操作保留恢复记录。
- 清理失败不再覆盖为“上次网络清理未完成”，保留原始原因。
- 主动停止后台时停止自有组件服务，保留未完成恢复记录和提示，然后停止 Link 后台并关闭界面。普通断开仍保留后台恢复重试；卸载与组件替换仍要求清理成功。
- 功能未开启但存在清理失败时，功能页面仍显示恢复原因。

本地 C# 自检和 PowerShell 命令替身验证通过。本机旧待确认网卡经过安装日志与 GUID 核对后恢复，已安装程序与测试产物摘要一致；局域网重新取址，并通过真实退出选项验证界面关闭、Link 后台及两项组件服务停止。两台 Windows 跨网业务与重启恢复不属于本次验证结论。

只更新 Windows 客户端，服务端无需升级。旧版缺少 GUID、创建结果不明确且网卡仍存在时，需要管理员核实设备归属后恢复；新版不会自动删除归属不明的网卡。更新入口仍保留清理失败保护，不能用覆盖安装或删除恢复记录绕过。
