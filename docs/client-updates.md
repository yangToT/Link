# 客户端更新

从 **0.2.0-alpha.8** 开始，Windows 客户端可检测、下载并由用户确认安装更新。alpha.7 及以前需要先手动安装一次新版。

## 使用

- 客户端界面启动时检查一次，之后每 6 小时检查；收起到托盘仍会检查，仅后台服务运行时不弹出提醒。
- 发现新版本提供“立即更新”“稍后更新”“跳过此版本”。立即更新先下载，进度按实际字节显示，可取消。
- 完成 SHA-256 校验后提供“立即重启”“稍后重启”。重启指 Link，不重启 Windows。下载完成不会自动中断网络。
- “稍后”延后 24 小时，偏好保存到本机，退出再打开也保留；跳过只影响该版本。设置页的手动检查可重新选择已跳过的版本。
- 安装前请求 Windows 管理员权限，再次校验发布记录与文件，备份现有程序，停止 Link 后台并恢复其网络规则，再替换程序、启动和检查后台版本。过程中连接会短暂中断，入口设备更新会影响依赖它的访问。
- 设备身份、服务端地址、组件启用状态和连接偏好保留。失败回退保留原程序备份；若系统文件锁等问题同时阻止回退，会显示失败，不冒充安装成功。
- 检查或下载失败时继续运行当前版本；安装准备失败也不会停止连接。已下载包不在下次开机时静默安装。

## 发布约定

**Git push 不等于发布更新。** 客户端读取 GitHub Releases，忽略草稿、没有完整 Windows 客户端包的发布、当前和更低版本。带预发布标记的客户端接收预览及稳定版；稳定客户端只接收稳定版本。

默认发布仓库为 `yangToT/Link`，开源分支可在 `client/Update.cs` 的 `Repository` 常量中改为自己的仓库，再构建客户端。没有向服务端或 GitHub 上传设备配置、加入凭据、SSH 信息或网络诊断；检查只请求公开发布元数据和资产。服务端不需要增加端口或后台更新服务。

每个可更新版本需要：

1. Git 标签 `v<版本>`，`Common.Version` 与包版本一致；版本使用三段数字与可选预发布标识，例如 `0.2.0-alpha.9`。
2. 发布 `Link-client-windows-amd64-v<版本>.zip` 和 `SHA256SUMS.txt`，二者属于同一个 Release。建议先上传完整资产，再结束草稿状态。
3. 使用 `python deploy/package.py --version <版本> --client-only` 打包；脚本写入 `client-update.json`（格式版本、程序版本、最低更新器版本），并包含固定安装文件及第三方许可证。
4. 保留已有 Release 资产，不用同一个版本号替换不同二进制。

TLS、固定仓库及受限制的下载重定向校验发布来源；SHA-256 和 GitHub 资产 digest（存在时）校验完整性。客户端目前没有代码签名或独立离线签名信任链。客户端不会执行更新包指定的任意安装脚本，也不会接受其他设备指定的下载源。格式不兼容时需手动更新。

## 文件与恢复

- 用户偏好与下载缓存：`%LOCALAPPDATA%\Link\updates`，不含设备凭据。可在 Link 完全退出后手动删除此缓存。
- 受保护的安装暂存及结果：`%ProgramData%\Link\updates\<任务 ID>`；普通用户只读，管理员与 SYSTEM 可写。
- 程序备份：`%ProgramData%\Link\backups\core-<时间>`。
- 检测不替代后台健康检查；新版本后台启动成功也不等于所有远端服务已经可达。跨网恢复以实际设备状态和访问结果为准。

## 本次验证范围

已验证版本与通道筛选、延期/跳过、源地址限制、校验摘要不一致、压缩包路径拒绝、更新按钮状态、真实 GitHub 发布列表读取，以及本机真实安装事务的失败回退和成功升级。未来版本从正式 Release 提示、下载到重启的完整用户操作链，仍需在下一版发布后验证；不将这些分项测试描述为已经完成跨版本自动升级验收。
