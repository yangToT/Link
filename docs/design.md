# 需求与架构基线

状态：讨论已确认的产品方向与待验证的实现方案。本文不表示功能已实现。

## 产品目标

其他用户能独立部署服务端，在多台 Windows 设备上安装客户端，加入同一专用网络后访问获准设备、远程桌面和资源。由选定的网络入口设备转发对其所在网络的访问，并承接其他网络中对客户端服务的访问。

用户不手动配置路由、掩码、NAT 和映射端口。应用账号、数据库凭据及必要的业务地址仍属于原有应用配置。

## 已确认的交互

1. 服务端部署在有公网 IP 的 Linux 服务器；不要求购买域名。
2. 客户端输入服务端地址及加入凭据，完成注册和连接。
3. 初始管理员加入码由服务端安装流程输出；不是先访问私有网页领取。
4. 后续加入码由已连接的管理员在管理中心生成。
5. 首次连接成功后可自动打开管理网页；客户端始终提供快捷按钮，自动重连不重复打开网页。
6. 管理网页和管理 API 仅在专用网络内开放，仍有用户权限校验。
7. 管理员可指定网络入口；指定设备的客户端顶部持续标识该身份。
8. 支持开机启动、自动连接、后台运行及从客户端启动 mstsc。
9. 支持踢下线、停用设备。踢下线后等待手动重连；停用后不得自动恢复访问。
10. 多台设备使用同一安装包加入，不以两台设备为固定拓扑。

## 组件边界

| 组件 | 职责 |
| --- | --- |
| 产品管理服务 | 身份、权限、设备、入口、映射配置、操作记录 |
| 组网组件 | 加密、设备间连接、穿透、必要时中继 |
| Windows 后台服务 | 连接保持、系统网络规则、服务转发与恢复 |
| Windows 界面 | 连接、设备快捷操作、本机服务与偏好设置 |
| 私有管理网页 | 多设备与整个实例的管理 |

NetBird 是优先验证的组网底座；不把全部产品需求视为其默认已有功能。公网 IP 接入与证书引导、私有管理边界、Windows 反向转发均需验证。

客户端采用 C# / WPF，控制服务采用 Go，网页为内嵌静态资产，网络底层为 NetBird 0.79.0。

## 接入、管理与信任

- 公网只提供客户端接入、必要的身份引导、连接协调和中继能力。
- 管理网页和管理 API 不通过公网反向代理暴露，也不能只依赖隐藏地址。
- 首次部署生成有时效、一次性使用的管理员加入凭据。
- 通过服务端管理命令提供失联后的管理员恢复流程，不能依赖已经失联的设备。
- 支持 IP 地址时，安装输出与客户端加入流程应建立可验证的服务端身份。具体证书分发、指纹绑定及更新方式须单独验证；不能关闭 TLS 校验。
- 客户端保有独立设备身份；普通客户端不持有全局管理员密钥。
- 撤销权限需作用于实际通信。对配置传播、现存会话和失联设备设置明确的撤销时限及状态反馈，不能仅修改在线标识。

## 访问入口网络

入口识别路由和名称解析信息，产品生成并下发访问规则。不能假设所有私有地址都属于同一个网络。

自动发现不完整时允许提供业务网址或目标地址进行补充，产品仍负责生成网络配置。网段重叠时必须明确选择目标网络，不静默访问错误设备。

只管理本产品创建的系统规则。断开、角色变更和卸载应清理或恢复相应规则。

## 发布本机服务

对于未安装客户端的调用方，默认通过入口设备可达的地址承接访问，再转发到目标客户端。产品自动分配并维护入口端口，避免多设备服务端口相同时发生冲突。

前提是调用方所在网络允许访问入口设备。若服务器与办公设备之间存在隔离，必须改变入口部署位置或调整网络策略；客户端无法凭空消除该限制。

服务发现类应用需要对外公布可达地址。用户已接受一次性生成或导入 IDEA 专用运行配置，之后正常运行与调试。产品生成所需参数，不修改应用实际监听端口。

普通端口发布与特定注册框架的参数生成分离：通用界面不绑定某一注册中心。适配器依据实际框架版本验证，不能宣称任意程序未经接入就能自动正确注册。

应用继续负责自身注册、心跳和注销。系统负责转发、地址分配、健康探测与配置更新，避免应用停止后产生虚假健康实例。入口地址变化时需同步更新应用配置，必要时提示重启；不能无条件承诺永久只配置一次。

## 状态语义

| 动作或状态 | 行为 |
| --- | --- |
| 关闭窗口 | 按设置驻留后台 |
| 主动断开 | 停止当前连接，避免自动重连立即抵消操作 |
| 踢下线 | 管理端终止访问，需客户端手动重新连接 |
| 停用 | 撤销授权，直到管理员恢复 |
| 入口设备离线 | 相关资源与映射显示不可用，不等同于所有设备断网 |
| 自动重连 | 针对非主动的连接中断恢复连接 |

## 界面方向

- 产品暂名 Link；正式名称尚未核定。
- 管理网页为简洁实色工具界面；Windows 客户端使用半透明毛玻璃。
- 使用设备、网络入口、资源、服务映射等通用术语。
- 原型为独立模拟，尚未实现两端联动和真实网络操作。

## 开源与部署范围

当前目标是每个使用者可独立部署一个实例，支持多用户和多设备；不默认扩展为集中运营的公共多租户 SaaS。

自有代码许可证已确定为 Apache-2.0。所选 NetBird 版本及其各目录、依赖、分发产物的许可证必须在集成和发布时核查，保留相应声明。
