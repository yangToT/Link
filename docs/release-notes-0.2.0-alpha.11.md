# Link 0.2.0-alpha.11

修复取得局域网地址后，一次路由检查不匹配就立即删除网卡、反复重新取址的问题。

- 局域网路由暂时不可用或选到其他网卡时，保留当前网卡与地址最多 30 秒；恢复后继续原连接，持续异常则清理。该等待机制原先只覆盖基础专用网络，现覆盖局域网路由。
- 状态和复制诊断记录实际选择的网卡编号、期望网卡及路由前缀；不再将所有不匹配都误报为 TUN 抢占。
- 只有 Windows 确认地址可用时才显示已取得地址，不将重复地址或尚在检测的地址显示为就绪。

本次仅更新 Windows 客户端，服务端保持 alpha.10。设置中检查更新，下载后重启 Link 即可；无需卸载、重新加入或重新安装局域网组件。

回归覆盖无路由、暂时走其他网卡、恢复后的状态、30 秒等待上限、归属记录和失败诊断。家庭设备的某次健康采样显示路由正确且未运行代理 TUN；暂态异常的具体系统触发源尚未取得现场证据，因此不将此版本解释为已解决所有代理或路由冲突。

真实隔离 DHCP 连接保持超过 100 秒；注入一次路由检查异常后，在原网卡和原地址上恢复并完成清理。该异常由测试注入，未对宿主机其他网卡制造实际路由冲突。

发布后：GitHub 构建通过，本机已升级并验证身份和网络基线保留；用户确认家里更新后观察期间保持连接，服务端连续采样一致。入口升级重连后，家里自动恢复相同 MAC 和地址。详见验证记录。
