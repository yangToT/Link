# 控制通信与实时状态

0.2.0-alpha.1 已在一台 Linux 云端和一台 Windows 客户端完成升级，实测通过两类 SSE 连接及私有管理登录。升级前已打开的旧网页需要刷新或从客户端重新打开；双机及长期运行范围见验证记录。

| 链路 | 变更前 | 当前源码 |
| --- | --- | --- |
| 管理网页 → 服务端 | 每 5 秒 GET 全量状态 | 打开时 GET 一次，随后通过 SSE 接收状态变化 |
| Windows 后台 → 服务端 | 每 5 秒 POST 心跳，响应携带配置 | 每 15 秒 HTTPS 心跳；SSE 主动推送设备和配置变化 |
| Windows 界面 → 本机后台 | 每 3 秒命名管道读取状态 | 保留；不产生公网/云端请求 |
| 控制服务 → NetBird 管理 API | 每 5 秒同步实际节点状态 | 保留现有对账，变更后通知订阅者 |
| 应用、文件、远程桌面流量 | 专用网络承载 | 不进入 SSE，也不转换成 JSON 控制消息 |

## 选择 SSE 的原因

目前通信以服务端下发最新状态为主，用户操作和设备报告是低频请求。SSE 配合 HTTPS POST 可直接复用现有认证、CSRF 和响应处理，不需要新增一套 WebSocket 请求编号、双向消息确认及重放协议。原生 EventSource 支持断线重连。若将来增加持续双向高频交互，再单独评估 WebSocket。

心跳与轮询不同：心跳报告设备实际存活和本机服务状态，SSE 连接存在不能代替这些事实。后台周期性同步也不是数据包中转机制；更换状态通信不会直接提高 VPN 隧道吞吐。

## 行为与安全边界

- 网页使用仅专用网络可访问的 `GET /api/events`，保持现有 HttpOnly 会话 Cookie 与设备来源 IP 绑定。POST 操作仍校验 Origin 和 CSRF。
- 后台使用公网控制入口上的 `GET /agent/events`，设备令牌只在 Authorization 头内传递。复用原有 TLS 证书链、主机名与加入指纹验证，不在 URL 放凭据。
- 首次连接及每次重连均发送当前完整状态；只在有效内容变化时再次推送。最后心跳时间及版本数字单独变化不会广播全量状态。
- 配置状态带服务启动标识与递增版本。客户端拒绝同一服务启动中的旧版本，也拒绝已经淘汰的启动标识，防止心跳响应与推送乱序覆盖。
- 服务端使用合并通知，不为慢客户端累积事件队列。每个身份最多 4 个同类实时连接，写入有 10 秒超时，每 15 秒发轻量保活；保活不是重新创建 HTTP 请求。
- 会话过期或设备停用后重新检查权限并关闭流。正常管理操作完成后可立即推送；底层网络状态仍取决于真实探测/报告周期。不会把“命令已推送”等同于底层访问已成功撤销。
- Windows 后台对网络错误以 1–30 秒退避重连，遇到旧服务端 404 时减慢探测，15 秒心跳仍可获取状态。主动断开后取消订阅；旧连接的延迟回调不得重新启用网络。
- 本地服务停止时取消 SSE；服务端退出先结束事件流再关闭 HTTP 服务。流只持有已复制的快照，不在写网络时占用数据存储锁。

使用现有 HTTPS 端口，不新增安全组端口。若管理员另加反向代理，需关闭这些 SSE 路径的响应缓冲，并使读取空闲超时大于 15 秒。应先升级服务端，再升级 Windows 客户端；新版网页依赖新版事件接口。

## 验证

Go 本机 HTTP/TLS 测试覆盖初始快照、主动推送、重连补全、设备撤销、管理员会话撤销、公网管理隔离、连接上限、快照不共享可变数据，以及 HTTP/2 空闲连接存活。C# 自检通过本机 TCP 测试端点验证 SSE 鉴权头、接收、断线重连和撤销，同时检查帧长度及状态顺序。Playwright 使用合成 API 检查没有 5 秒定时拉取、实时更新、自动重连、授权撤销和页面交互。

部署后另实测：云端及客户端版本匹配、固定证书的客户端 SSE、私有网页 SSE、内嵌资源更新、公网管理接口隔离；本机更新前后默认路由、DNS 和 TUN 网卡状态一致。上述验证不包括代理链路持续运行、二层接入或两台真实电脑的组网验收。

依据：[SSE / EventSource 标准](https://html.spec.whatwg.org/multipage/server-sent-events.html)、[Go HTTP ResponseController](https://pkg.go.dev/net/http#ResponseController)。
